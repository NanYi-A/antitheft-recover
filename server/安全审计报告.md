# 防盗系统安全审计报告

> 审计日期：2026-08-16
> 审计对象：云端中继（`server/main.py` + `server/anti_theft.py`）、安卓端（`app/`）
> 方法：只读源码审计（未修改任何代码），聚焦"未授权获取后台管理员权限 / 远程执行 wipe / 信息泄露"三条攻击链

## 一、总体结论（先给结论）

**核心鉴权架构正确，不存在"绕过鉴权直接 wipe"的漏洞。** 但要堵住两个现实命门才能真正做到"除你之外无人能获取管理员权限"。

- 所有危险操作（下发指令 `wipe/lock`、删除设备、删除/清空照片、读取位置/照片/通知）都强制 `Depends(ctrl_auth)`，即必须持有 `CTRL_TOKEN`。
- 安卓 APK **不含** `CTRL_TOKEN`，客户端只持有注册时下发的设备级随机 token（`secrets.token_hex(32)`）。小偷拿到手机无法提取后台管理员 token。
- 因此"被入侵后台执行恢复出厂"的前提 = 攻击者拿到 `CTRL_TOKEN`。防泄露即防 wipe。

## 三、风险清单（按严重度）

### 🔴 [致命] 宝塔站点可能把项目目录文件当静态资源暴露
- 部署目录下含：`.ctrl_token`（CTRL_TOKEN 明文）、`anti_theft.db`（全部位置/照片索引/设备 token）、`anti_theft_photos/`、`anti_theft_albums/`、`ai_voice.db`。
- 若宝塔 Nginx 配了"网站目录"且允许静态文件访问 / 目录浏览，则任何人访问 `https://relay.example.com/.ctrl_token` 即可**直接拿到后台管理员 token**，进而可进控制台远程 wipe、删设备、下指令。
- **这是当前最大的单点风险，优先级最高。** 需在宝塔确认：站点是否纯反向代理（不服务本地文件）；若是静态站需加 `location ~ \.(db|token|py)$ { deny all; }` 并关闭目录索引。

### 🟠 [高] 设备注册接口 `at_register` 完全开放（无鉴权）
- `POST /anti-theft/register` 无需任何 token 即可调用，返回 `device_id + token` 并向 `at_devices` 插一行。
- 危害：攻击者可无限注册设备 → 刷爆数据库 / 撑满磁盘（DoS），并在你的控制台设备列表里灌入垃圾设备干扰判断。
- 信息泄露风险低（注册出的 token 是强随机，攻击者拿不到你的真实设备数据），但资源滥用与污染是实打实的。
- 建议：注册接口改为需 `ctrl_auth`，或限制来源 IP + 速率限制。

### 🟡 [中] 设备 token 走 URL query（report/poll/WS）
- 手机上报用 `?token=xxx`，WS 握手 `?device_id=&token=`。token 会出现在 Nginx 访问日志、uvicorn 访问日志、浏览器历史。
- 危害：若服务器日志被读取，设备 token 泄露 → 攻击者可伪造该设备上报垃圾位置/通知（污染你的数据，但**不能读取**你的数据，读取需 CTRL_TOKEN）。
- 建议：设备 token 改放请求头（如 `X-Device-Token` 或 `Authorization: Bearer`），避免写入 URL/日志。

### 🟡 [中] 下发指令接口未限制 cmd 白名单
- `at_command`（555行）接受任意 `cmd` 字符串，WS 在线时直接 `ws.send_text` 转发给手机。
- 当前安全依赖"手机端忽略未知 cmd"。若手机端对未知 cmd 处理不严谨则有隐患。
- 建议：服务端 `at_command` 限制 `cmd ∈ {activate,locate,photo,album,lock,wipe,realtime,stop,usage}`；手机端显式 reject 未知 cmd。

### 🟢 [低] 高德 Web Key 硬编码源码（anti_theft.py:80）
- 泄露后他人可用你的高德配额（位置查询是服务端做的，不直接泄露你的位置）。
- 建议：移到环境变量；高德后台配置"仅服务端 IP / 指定域名"白名单 + 配额告警。

### 🟢 [低] 相册路径遍历补强
- `at_album_file` 已挡 `..` 和 `/` 开头，但 Windows 下未挡 `\`，且未做 `realpath` 落目录校验。建议加 `os.path.realpath` 校验最终路径在 `AT_ALBUMS_DIR` 内。

### ⚠️ [需确认] 8001 明文端口是否已关闭
- 生产应仅经 Nginx 443(HTTPS/WSS) 访问，uvicorn 只监听 `127.0.0.1:8001`。
- 若 8001 仍对公网开放 HTTP，则 `CTRL_TOKEN` 在传输中明文 → 中间人可截获。
- 需确认宝塔进程守护启动命令为 `uvicorn main:app --host 127.0.0.1 --port 8001`，且云安全组/防火墙未放 8001 入站。

## 七、方案①限流实施（2026-08-16 10:10）

用户拍板：**不给 register 加 ctrl_auth**（会破坏"APK 不含后台 token"安全模型 + 加新设备需记管理员 token），改用**限流**堵住开放注册的资源滥用风险。

### 7.1 已做：服务端应用层兜底限流
- 文件：`server/anti_theft.py`
- 在 `at_register` 路由前加模块级 `_REGISTER_LIMIT` + `_register_allowed(client_ip)`：按 `X-Forwarded-For` 首跳真实 IP（回退 `req.client.host`）做 **60 秒滑动窗口、单 IP 最多 10 次注册**，超出返回 `429`。
- 手机正常注册只发生一次，不受影响；你后续加新设备（每设备注册一次）也在窗口内正常通过。
- `py_compile` 通过（10:10）。**部署**：覆盖上传 `anti_theft.py` → 重启 uvicorn 进程。

### 7.2 可选增强：宝塔 Nginx 层限流（在请求到 Python 前就挡）
> 服务端兜底已生效；Nginx 层作为更强一道，纯配置不改代码。在宝塔操作：

**步骤 1 — Nginx 全局 http 块加 zone**（宝塔 → 软件商店 → 已安装 → Nginx → 配置修改，在 `http { ... }` 内任意位置加）：
```nginx
limit_req_zone $binary_remote_addr zone=reg_limit:10m rate=6r/m;
```

**步骤 2 — 站点 server 块加精确匹配 location**（宝塔 → 网站 → relay.example.com → 设置 → 配置文件，放在反代 `location /` 之前）：
```nginx
location = /anti-theft/register {
    limit_req zone=reg_limit burst=3 nodelay;
    limit_req_status 429;
    proxy_pass http://127.0.0.1:8001;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```
> `location =` 精确匹配优先级最高，会接管 register 而不走通用反代；保存后点"重载配置"即可。

**步骤 3 — 验证**（连发多次应返回 429）：
```bash
for i in $(seq 1 15); do curl -s -o /dev/null -w "%{http_code}\n" -X POST https://relay.example.com/anti-theft/register -H 'Content-Type: application/json' -d '{}'; done
```
