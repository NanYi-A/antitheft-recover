# 应用使用分析功能（App 打开记录 / 当前前台 App / 已装 App）

> 状态：实现中（2026-08-14 启动）
> 决策：数据上传策略 = **一次性全量上传**（手机收到 `usage` 指令后上传最近 60 天按天分桶使用数据 + 前台 App + 已装列表；控制台切换时间范围/排序在浏览器本地完成，秒切、不再打扰手机）

## 一、功能需求

### 1. App 打开记录 / 使用时长（标签1）
- 数据源：`UsageStatsManager.queryUsageStats(INTERVAL_DAILY, now-60d, now)`，仅保留有前台时长的 app/天。
- 每条：包名、应用名、当天前台总时长(total_ms)、最近使用(last_used)、首次使用(first_used)、打开次数(launches, API28+)。
- 排序：**按最近使用时间(last_used)降序**。
- 时间范围选择器（控制台本地过滤，不重新请求手机）：
  - 今天 / 昨天 / 近三天 / 本周 / 上一周 / 近一个月 / 上个月
  - 「本周/上一周」按周一为一周起点（Locale.CHINA）；「上个月」= 上一自然月。
- 展示列：应用 | 最近使用(timeAgo) | 区间使用时长(合计) | 打开次数。

### 2. 当前前台 App（标签2）
- 数据源：`UsageStatsManager.queryEvents` 取最近 2 分钟内最后一次 `MOVE_TO_FOREGROUND` 事件对应的包名。
- 展示：应用名 + 包名 + 采集时间（带 timeAgo，越久越旧）。
- 注意：是采集时刻的快照，非实时。

### 3. 已装 App 完整列表（标签3）
- 数据源：`PackageManager.getInstalledApplications`。
- 展示：应用名 + 包名，标注 system(系统App)/user(用户App)。
- 列表可滚动；移动端适配。

### 4. 入口
- 设备详情页（主页）加按钮「应用使用情况」→ 新开独立页面 `/anti-theft/usage?device_id=XXX`（新标签页）。

## 二、权限
- `android.permission.PACKAGE_USAGE_STATS`（特殊权限，无法代码自动授予）。
- 未授予时：设置页显示「未授予 → 点击设置」，跳转 `Settings.ACTION_USAGE_ACCESS_SETTINGS`；控制台下发 `usage` 时若手机未授权，手机自动跳授权页并跳过采集（不上传空数据）。
- 无此权限时 `UsageStatsManager` 返回空，控制台显示「未授权」。

## 五、风险 / 备注
- `PACKAGE_USAGE_STATS` 必须手动授权，部分国产 ROM（小米/HyperOS）设置路径深，需在设置页引导。
- `getAppLaunchCount()` 仅 API28+，低版本 launches 留 0。
- 占用空间：at_usage 仅存最新一份 JSON，体积随 app 数量增长，可接受。
- 与既有 album/photo 一样走手动触发，不自动上报，不破坏隐蔽/省电。
